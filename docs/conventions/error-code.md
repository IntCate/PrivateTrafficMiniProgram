# 通用规范 - 错误码（error-code）

> 适用：快乐购商城 C 端 + 后台全部接口。前端按 `code` 做提示与跳转（401 → 重新登录），后端所有异常处理器统一出口。

---

## 1. 统一响应结构

```json
{ "code": 0, "message": "ok", "data": { } }
```

- `code`：业务码，`0` 恒为成功；
- `message`：可读信息（中文），成功为 `ok`；
- `data`：业务数据，失败时为 `null`。

## 2. 通用码（与 HTTP 语义对齐）

| code | 含义 | 说明 | 前端处理 |
| --- | --- | --- | --- |
| 0 | 成功 | — | 正常处理 |
| 400 | 参数错误 | `message` 指明具体字段 | 表单提示 |
| 401 | 未登录 / 登录过期 | token 缺失、无效或过期，或会话不存在 | **清除本地 token 并跳转重新登录** |
| 403 | 无权限 | 非本人资源或角色不足 | 提示无权限 |
| 404 | 资源不存在 | **统一口径**：商品/SKU/购物车项/地址/订单等资源不存在或已删除，一律返回本码，不使用模块段位码 | 提示资源不存在 |
| 409 | 业务冲突 | 幂等重复操作（如重复支付）、并发冲突 | 提示"请勿重复操作" |
| 429 | 请求过于频繁 | 限流 | 提示稍后重试 |
| 500 | 系统内部错误 | 未知异常 | 统一兜底提示 |

> 通用码设计为**唯一真相**：HTTP 状态码与之保持一致（401 场景同时返回 HTTP 401），便于网关与监控按 HTTP 层统计。

## 3. 业务错误码（模块分段）

| 段位 | 模块 | code | 含义 |
| --- | --- | --- | --- |
| 1000-1099 | 认证/登录 | 1001 | 登录 code 无效（wx.code2session 失败） |
| | | 1002 | 手机号获取/解密失败（getPhoneNumber） |
| | | 1003 | 头像昵称校验失败（昵称非法或头像域校验不通过） |
| 1100-1199 | 商品 | 1102 | 商品已下架 |
| | | 1104 | 库存不足（`data` 返回最大可购数量） |
| 1200-1299 | 购物车 | 1201 | 数量超出单次限购（最大 99；超库存用 1104） |
| | | 1203 | 结算商品包含不可售项（下架/库存为 0） |
| 1300-1399 | 收货地址 | 1301 | 地址数量超上限（默认 20 条） |
| 1400-1499 | 订单 | 1402 | 订单状态不允许当前操作（如取消非待支付订单、确认收货非待收货订单，重复支付用 409） |
| | | 1403 | 订单归属不匹配（越权访问他人订单） |
| | | 1404 | 金额校验失败（客户端上送金额与服务端计算不一致） |
| | | 1405 | 订单已超时未支付 |
| | | 1406 | 库存锁定失败（并发下单冲突） |
| 1500-1599 | 收藏 | 1501 | 收藏操作冲突（兜底异常场景；重复收藏幂等返回成功，不触发本码，见 api-design §10.2） |
| 1600-1699 | 优惠券/积分/售后 | 1601 | 优惠券不存在 |
| | | 1602 | 该券已领取 |
| | | 1603 | 优惠券已过期或未到生效期 |
| | | 1604 | 不满足使用门槛 |
| | | 1605 | 积分不足 |
| | | 1606 | 该订单已有进行中的售后申请 |
| 1700-1799 | 后台 | 1701 | 账号或密码错误 |
| | | 1702 | 用户名已存在 |
| | | 1703 | 不能禁用当前登录账号 |
| 1800-1899 | 微信对接 | 1801 | code2Session 调用失败（网络/参数） |
| | | 1802 | 微信服务器返回异常响应 |
| | | 1803 | 支付回调验签失败 |
| 1900-1999 | 系统 | 1901 | 系统配置缺失（如客服电话未配置） |
| | | 1902 | 文件上传失败 |
| | | 1999 | 未知业务错误 |

> **已废止段位码**（不再分配、不推荐使用）：`1101`、`1103`、`1202`、`1302`、`1401`。原"XX 不存在"类场景**一律返回通用码 `404`**（见 §2），与 HTTP 语义对齐、前端统一按 404 分支。

## 4. 使用约定

- 后端**只抛出业务码**，禁止直接返回 `500` 冒充业务失败；未知异常由全局处理器兜底为 HTTP `500` + 业务码 `1999`；
- 一个接口不同错误返回的 `message` 必须稳定无歧义，前端不做字符串匹配，一律按 `code` 分支；
- 新增错误码：在对应模块段位表尾追加，**不允许复用已占用的 code**；并在此文档维护后同步到 api-design 文档对应接口的错误列；
- 冲突编码（400 与 409 边界）：参数格式问题用 400；语义冲突（重复操作、状态不允许）用 409 或对应业务码。
