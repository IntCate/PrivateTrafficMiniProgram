# 快乐购商城 - 产品需求文档（PRD）

> 项目：快乐购（自营私域商城小程序）
> 版本：v1.0
> 依据：`mall-miniapp-uni` 前端 12 个页面与 `docs/api-design.md` 推导，作为后端开发的需求基线。

---

## 1. 产品概述

快乐购是微信小程序端的自营私域商城，面向普通消费者提供"逛 → 加购 → 下单 → 收货"完整购物链路，并包含收藏、优惠券、会员积分等运营能力；面向内部运营人员提供商品/订单/会员/运营位的后台管理能力（后台为规划阶段）。

| 项 | 说明 |
| --- | --- |
| 终端 | 微信小程序（uni-app / Vue3），后端服务为 RESTful API |
| 商业模式 | 自营 B2C，微信支付收款（首版可用 mock 代付） |
| 一期范围 | C 端全链路 + 微信登录；后台管理为二期 |

**需求边界**：以 `docs/api-design.md` 接口清单为唯一接口契约，以 `docs/database-design.md` 为唯一数据契约，本文档只定"要什么、规则是什么"，不重复三表细节。

## 4. 核心业务规则

> 以下规则与数据库设计 §6「数据一致性要点」配套，是后端 service 层的硬性约束。

### 4.1 登录规则

- 登录即注册：微信 `code` 换 `openid` 后，`member` 表不存在 → 自动创建会员（默认昵称"快乐购物家"、等级 `bronze`（普通）、积分 0）；
- 同一 `openid` 永久唯一（唯一索引），不存在"重复注册"；
- `session_key` 仅服务端保存，不下发前端；头像昵称需用户主动通过"头像昵称填写能力"完善，登录阶段不强求。

### 4.2 购买与库存规则

- 库存模型：`stock`（真实库存）+ `lock_stock`（已锁未支付），可售余量 = `stock - lock_stock`；
- 下单（`status=pending`）即预占：`lock_stock += qty`；支付成功 → `stock -= qty` 并释放 `lock_stock -= qty`；
- 超时未支付（30 分钟）由定时任务关闭订单并回补 `lock_stock`；
- 取消/超时关闭的订单若已占用库存一律回补，保证不超卖不丢量；
- 并发扣减依赖事务内 `SELECT ... FOR UPDATE` 行锁，禁止应用层自旋。

### 4.3 金额规则

- 所有金额以服务端 `order_item.price × quantity` 累加为准，**禁止信任客户端上送的金额**；
- 金额类型 `DECIMAL(10,2)` 元，前端展示符号 `¥` 由前端处理，接口只回数字；
- 优惠券/积分抵扣必须重新在服务端计算（券是否可用、是否过期、是否被占用）。

### 4.4 订单状态机

```text
pending(待支付) ──支付成功──→ paid(已支付/待发货)
   │                              │
   │超时30min/主动取消              │ 发货
   ▼                              ▼
cancelled(已取消)            shipped(已发货/待收货)
                                  │ 确认收货
                                  ▼
                            completed(已完成)
                                  │ 售后(二期)
                                  ▼
                            refund(退款/售后)
```

- 状态变更前置校验：`pending → paid/cancelled`、`paid → shipped`、`shipped → completed`，其余流转一律返回业务错误码；
- 已 `completed/refund` 的订单不可取消、不可重复发货。

### 4.5 默认地址规则

- 每个会员仅一个默认地址；设为默认时，其余地址自动取消默认；
- 新增地址表为空时首条自动设为默认；
- 下单地址做快照，后续修改地址不影响历史订单展示。

### 4.6 购物车规则

- 同一会员 + 同一 SKU 幂等：重复加购合并数量（`uk_user_sku` 唯一索引）；
- 数量范围 `1 ~ min(99, 可用库存)`：超出单次限购返回 `1201`、超出库存返回 `1104`；勾选状态影响"结算"仅统计选中项。

### 4.7 收藏规则

- 同一会员对同一商品唯一（唯一索引），重复收藏幂等（返回成功）；
- 商品下架/删除后收藏列表仍可展示但标记不可购买。

### 4.8 订单号规则

- 格式 `K + yyyyMMddHHmmss + 3 位随机`（与前端 `K202608301420` 展示兼容）；
- 全局唯一（随机部分碰撞时重新生成）。

### 4.9 头像昵称规则（合规）

- 头像：`button open-type="chooseAvatar"` 用户选择 → 临时路径 → 上传至服务端存储后存永久 URL；
- 昵称：`input type="nickname"` 由微信键盘辅助填写；
- 服务端校验头像 URL 属于自有存储域、昵称长度 1-20 字并过滤敏感词，禁止客户端直接提交外部 URL 为头像。

## 5. 非功能需求

| 类别 | 需求 |
| --- | --- |
| 性能 | 商品列表/详情、首页聚合 P95 < 300ms（单机压测指标）；列表查询必须走索引 |
| 并发 | 同一 SKU 同刻加购/下单不超卖；积分/券发放不超发（行锁） |
| 安全 | HTTPS 强制；`SECRET_KEY`/`appSecret` 仅环境变量；手机号/地址仅在对外可见场景（后台列表、日志、匿名接口）脱敏，本人数据接口完整返回（口径见 api-design §1.1）；接口防越权（按 user_id 归属校验） |
| 可用性 | 定时任务断点恢复；订单超时关闭幂等（重复执行无害） |
| 可维护 | 统一响应/错误码/日志规范；Alembic 迁移；ruff + mypy + pytest 强制通过 |
| 合规 | 用户协议与隐私政策声明；微信登录/手机号能力按要求申请权限 |

## 6. 版本计划与验收口径

### 6.1 P0（一期 · 必须）

微信登录（mock 可用）→ 首页/分类/商品/搜索 → 购物车 → 地址 → 订单（支付 mock）→ 收藏 → 会员中心。验收：前端 12 个页面全部切后端数据且主链路（浏览-加购-下单-支付mock-收货）可跑通。

### 6.2 P1（二期）

微信支付真实接入、订单超时关闭任务、售后、优惠券、积分流水、管理后台全部接口与后台页面。

### 6.3 验收口径

每期交付以接口文档用例（Postman/Apifox 集合）为准：核心用例（加购幂等、下单锁库存、取消回补、并发下单、默认地址唯一、订单状态机非法流转）必须覆盖并有通过记录。
